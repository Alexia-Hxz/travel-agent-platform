# 项目演示脚本

## 演示前准备

1. 在 `backend/.env` 配置自己的百炼与 Tavily Key。
2. 在项目根目录执行 `docker compose up --build`。
3. 打开 http://127.0.0.1:5173。

## 三到五分钟演示流程

1. 创建一个旅行项目，例如“杭州三日游”，填写旅行日期和预算。
2. 进入旅行详情，添加西湖景区、酒店和餐厅等收藏地点。
3. 在每日行程中为不同日期添加开始时间、结束时间和备注，展示时间线和日期校验。
4. 上传机票、酒店订单、菜单或攻略图片，点击“解析文件”查看 OCR 提取结果。
5. 对上传的旅行图片点击“使用 Agent 分析”，展示识别出的地点或行程建议；修改任意字段后点击确认保存，说明系统始终保留人工审核环节。
6. 打开旅行规划 Agent，输入“根据现有行程补充杭州三日安排”，勾选联网搜索，展示预算估算、冲突提醒、推荐卡片（酒店 / 美食 / 景点分组、每项配图、住几晚 / 吃几次可调）和工具执行轨迹。
7. 勾选几个推荐项目加入收藏地点，再用“对话式调整”说一句“把第二天下午换成室内的项目”，展示草案预览与逐项确认后才写入行程。

## 演示重点

- 前后端都使用 TypeScript/Python 的结构化类型和 REST API。
- 联网来源会在结果中展示，不把外部信息伪装成系统事实；API 原始链接不直接暴露给用户。
- 多模态结果与调整草案都必须由用户确认，避免模型直接修改行程。
- 核心数据保存在 SQLite，上传文件持久化在本地数据目录。
- 预算是“基础预算 + 已选推荐”的诚实口径：住宿与餐饮不预收、不重复计费，
  酒店按“住几晚”、美食按“吃几次”计入。

> 2026-09 变更：原先第 6 步演示的“城市知识库（RAG 检索）”功能已整体删除
> （实测检索恒为 0 条），演示流程里不再有这一步。

## 演示后清理

```powershell
docker compose down
```

本地数据会保留。如需清空演示数据，手动删除 `backend/travel_agent.db` 和 `data/` 下对应内容；不要删除 `.gitkeep` 文件。
